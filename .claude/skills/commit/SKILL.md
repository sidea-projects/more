# 커밋

규칙: `docs/rules/git-workflow.md`의 '브랜치'와 '커밋' (CLAUDE.md로 이미 불러와 있다).

"커밋 메시지 써줘"면 메시지 초안만 보여 주고 멈춘다.

## 순서

1. **커밋 대상**
   - 스테이징된 변경이 있으면 그것만, 그대로 한 커밋으로 한다. 나머지는 남아 있다고 한 줄만 알린다.
   - 없으면 `git status`와 `git diff HEAD`를 보고 이번 작업의 파일을 대상으로 한다. 타입이 다르거나 관계없는 작업이 섞여 있으면 나누자고 제안한다.
   - 바뀐 게 없으면 알리고 끝낸다.

2. **`main`이면 브랜치부터**
   - 관련 이슈 번호를 묻고, 규칙대로 이름을 제안해 `git switch -c`로 만든다.
   - 그래도 `main`에 커밋하겠다고 하면, push 하면 CI 없이 바로 운영 배포된다고 알리고 커밋만 한다.

3. **메시지 쓰기**
   - 제목은 규칙대로, 마침표 없이.
   - 본문은 diff만 봐서는 모르는 내용(왜 이렇게 했는지)이 있을 때만, 제목 아래 빈 줄 뒤에 `- ` 목록으로 쓴다.

4. **확인 (필수)**
   - 커밋마다 메시지와 파일 목록을 보여 주고 확인을 받는다.

5. **커밋**
   - 스테이징된 게 없었으면 대상 파일을 이름으로 `git add` 한다. `git add -A`/`.`, `.env`·비밀 값 파일은 안 된다.
   - 메시지는 heredoc으로 넘긴다.

   ```sh
   git commit -F - <<'EOF'
   feat: 메시지 작성 화면 추가

   - 받는 사람·내용 입력 폼
   EOF
   ```

   - Husky가 실패하면 `--no-verify` 쓰지 말고 원인을 고쳐 다시 커밋한다.
