# Git 작업 규칙

## 작업 흐름

1. 이슈를 만든다 (버그·기능 양식).
2. main에서 브랜치를 딴다.
3. 커밋하고 push 한 뒤 main으로 PR을 올린다.
4. CI가 통과하면 Squash merge 한다.
5. main에 들어가면 Cloudflare가 자동으로 배포한다 (빌드 → DB 마이그레이션 → 배포).

## 브랜치

`<타입>/<이슈 번호>-<설명>` 형식으로 짓는다. 영어 소문자, 숫자, `-`만 쓴다. 이슈 번호는 없으면 빼도 된다.

```sh
git switch -c feat/12-message-write
git switch -c fix/login-error
```

규칙과 다르면 PR의 CI가 실패한다.

## 커밋

`<타입>: <제목>` 형식으로 쓴다. 제목은 한글로, 무엇을 했는지 짧게 쓴다.

```
feat: 메시지 작성 화면 추가
fix(api): 전송 실패 시 500 에러 수정
```

범위(`api`)는 선택이다. 영어 소문자와 `-`만 쓴다.

| 타입       | 언제                                     |
| ---------- | ---------------------------------------- |
| `feat`     | 새 기능                                  |
| `fix`      | 버그 수정                                |
| `design`   | 화면 디자인 변경 (레이아웃, 색, 간격 등) |
| `style`    | 코드 포맷만 변경 (동작·화면 변화 없음)   |
| `refactor` | 동작은 그대로, 코드 구조만 개선          |
| `perf`     | 성능 개선                                |
| `test`     | 테스트 추가·수정                         |
| `docs`     | 문서                                     |
| `chore`    | 설정, 패키지 등 잡일                     |
| `build`    | 빌드 설정                                |
| `ci`       | CI 설정                                  |
| `revert`   | 이전 커밋 되돌리기                       |

커밋할 때 Husky가 형식을 검사한다. 타입 목록을 바꾸면 `commitlint.config.js`, `.github/workflows/ci.yml`, `.github/workflows/pr-title.yml`을 같이 고친다.

## PR

- 제목은 커밋 규칙과 같다. Squash merge 하면 PR 제목이 main의 커밋 제목이 된다. 규칙과 다르면 CI가 실패한다.
- 본문의 `close #12`로 이슈를 연결하면 머지할 때 이슈가 자동으로 닫힌다.
- 이슈 제목도 같은 타입으로 시작한다 (`fix: `, `feat: `).
